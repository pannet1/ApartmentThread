Thread Router

The radio bridge. Battery sensors speak Thread; Home Assistant does not, so something has to join the two networks. It is one radio plus three pieces of software on the server — and it is the least understood part of the build.

Component identity — BR-1

ESP32-H2 dev board flashed with OpenThread RCP firmware, plugged into the Radxa, with the border-router service running on the server and one Thread dataset issued for the whole network. Change the radio, the firmware image or the border-router software and it becomes BR-2 — a fresh commissioning test and a fresh proof sequence. It fails independently of the server it sits on.

Thread Border Router Stack Active · Proven on Hardware

All three components of the border router stack are now live and operational on the Radxa Zero 3E: (1) Native OpenThread RCP firmware verified on the ESP32-H2 (HDLC-Spinel over UART2 at 460,800 baud), (2) otbr-agent running in Docker in network state leader, and (3) active operational dataset ApartmentThread (Channel 15, PAN ID 0x1234) issued and exposed via local REST API (http://127.0.0.1:8081). BR-1 — 802.15.4 Thread Radio
M5Stack ESP32-H2 Thread/Zigbee Gateway Module (SKU M141). Stackable M-Bus module containing the ESP32-H2-MINI-1 transceiver. Physical reality: Has no onboard USB Type-C port. The underside has exposed male pins with zero pin labels; the top enclosure houses female header sockets, an 8-bit DIP switch, and the bare 6-hole "Burning Port". Pre-flashed from the factory with OpenThread Radio Co-Processor (RCP) firmware and wired to the Radxa SBC via 3.3V UART to turn it into a local Matter/Thread Border Router.

Hardware Anatomy & Connector Layout

Why this board's layout is confusing

As seen in the photo above, the physical hardware defies common development board expectations:

  • Labels are completely absent on the underside: The bottom male pins protrude through blank white plastic with zero pin names, numbering, or polarity markers.
  • Top-side labels reference M5 hosts, not raw pins: The silkscreen inside the box does not label pins as 1 to 30. Instead, it features a multiplexing matrix referencing Core, Core 2, and Core S3, because the module was engineered to stack onto three different generations of M5Stack host controllers via its 8-bit DIP switch.
  • The "Burning Port" has no connector: The 6-pin download interface is just a row of unpopulated plated through-holes (bare holes in the PCB) expecting pogo pins or soldered legs.

M-Bus 30-Pin Dual-Row Connector Layout

The module features a standard M5Stack 30-pin M-Bus connector (2×15 pins, 2.54mm pitch). It has female pass-through sockets inside the top enclosure cavity and male header pins protruding from the underside base.

Proof sequence — cheapest failure first

  1. Server up and reachable with the WAN cable out.
  2. Radio on RCP firmware; server detects it.
  3. Border-router service running; Thread network appears and survives a reboot.
  4. Commission a store-bought Thread device — any off-the-shelf Matter-over-Thread sensor. This is the whole test: if a known-good device can't join and report, a custom sensor never will. closes O-07
  5. Remove and re-add it; confirm it works after a server reboot with the WAN out.
  6. Only then start the custom presence sensor.

Full sequence with pass/fail gates: Stage 2 · Thread Border Router. Host hardware metrics are documented in Server Specifications.

Why this comes before the sensors

Proving the radio stack with a cheap, off-the-shelf Thread device costs far less than committing to the full custom PS-1 presence-sensor kit, and it tests the exact same failure mode: whether the border router actually works end-to-end. A failed test on a low-cost store-bought sensor is cheap to debug; a failed test after sinking the entire PS-1 bill of materials is not. Buy the router parts and one cheap test sensor together — before any presence sensor — and move the biggest unknown to the front of the queue. Authoritative prices for every line are maintained in the Bill of Materials; this page intentionally duplicates none of them.
