Stage 4 — Switch Plates (Tinxy 4+1 Fan)

Fitting smart switch modules behind physical modular wall plates in each room. The onboard Espressif ESP8266 microcontroller delivers true local-first control via ESPHome, Tasmota, or Tinxy's local HTTP/MQTT API with zero vendor cloud dependency, while physical wall switches remain 100% functional offline.

Stage 4 Objective

Deploy Tinxy 4 Node Smart Switch modules with fan regulation behind modular wall switch plates in Hall, Study, and Bathroom. Establish 100% local control via ESP8266 (ESPHome or local HTTP API), verify Neutral conductor presence (O-11), and confirm that mechanical wall toggles retain instant manual override with the server offline (O-18).

The mains voltage boundary

All in-wall switchboard work involves 230 V AC mains electricity and must be performed with the main MCB isolator switched OFF by a qualified electrician. Never touch live conductors.

1. Electrician Pre-Installation Checks

Before fitting any hardware into the conduit boxes, hand over these mandatory checks:

  1. Confirm Neutral wire presence: Ensure a continuous Neutral conductor (typically black or blue wire) is present inside each targeted switchboard (Hall, Study, and Bathroom). The Tinxy module requires active AC neutral to power its internal power supply, ESP8266 core, and relay coils. closes O-11
  2. Ceiling fan motor rating: Confirm the fan regulator channel is wired to standard AC induction ceiling fans (60–75 W). Tinxy uses multi-step capacitor regulation to deliver silent, hum-free speed control.
  3. Box depth and clearance: Standard Indian modular flush boxes (Anchor Roma, Crabtree, Legrand, etc.) must have at least 45 mm internal depth to accommodate the module behind the switches without crushing mains wire joints.

2. Physical In-Wall Module Hookup

Fit one Tinxy 4 Node Smart Switch with Fan Regulators (SW-1 Component Specs) per room behind the modular switch plate:

  • Connect Phase (L) from the mains circuit breaker to the module's L terminal.
  • Connect Neutral (N) from the conduit neutral bus to the module's N terminal.
  • Connect Load outputs (L1, L2, L3, L4) to the respective room lighting fixtures and bathroom exhaust fan.
  • Connect the Fan regulation output (F) directly to the ceiling fan motor wire.
  • Wire the Switch inputs (S1–S4, SF) directly to the existing mechanical wall rocker switches. Physical switches act as local trigger inputs to the secondary coprocessor, ensuring that flipping a wall switch toggles the load with sub-10ms response regardless of network state. closes O-18

3. Local ESP Integration (The ESP8266 Advantage)

Unlike Tuya-based modules that require cloud developer portal accounts, temporary API tokens, and internet handshakes, Tinxy is built on the Espressif ESP8266. This enables two distinct local control paths:

Option A: Native ESPHome Firmware (Recommended for Local-First Purists)

Tinxy multi-node modules utilize a dual-MCU architecture: the ESP8266 communicates with the relay/fan coprocessor via an internal serial UART bus at 9600 baud. You can flash ESPHome directly onto the ESP8266 for native Home Assistant push integration:

  1. Temporarily desolder the small W2 and W3 solder bridge pads on the back of the PCB to isolate the ESP8266's TX/RX lines from the coprocessor during programming.
  2. Connect a 3.3V USB-to-UART adapter to the 3.3V, GND, TXD, and RXD pads. Hold the onboard button while powering up to enter bootloader mode.
  3. Flash ESPHome using esptool.py or the ESPHome Web Flasher.
  4. Resolder the W2 and W3 bridge pads so the ESP8266 can talk to the coprocessor again.

Example ESPHome YAML configuration snippet for the UART interface:

uart:
  id: uart_bus
  tx_pin: GPIO1
  rx_pin: GPIO3
  baud_rate: 9600

switch:
  - platform: template
    name: "Light 1"
    turn_on_action:
      - uart.write: "#1100#"
    turn_off_action:
      - uart.write: "#1000#"
  - platform: template
    name: "Light 2"
    turn_on_action:
      - uart.write: "#2100#"
    turn_off_action:
      - uart.write: "#2000#"

fan:
  - platform: speed
    name: "Ceiling Fan"
    output: fan_output
    speed_count: 4

Home Assistant discovers the module automatically via the native ESPHome API with zero cloud and sub-millisecond local response. closes O-10

Option B: Tinxy Local API / Home Assistant Integration (Plug-and-Play)

If you prefer not to open the heat-shrink casing or solder:

  1. Power on the module and complete initial Wi-Fi pairing to your dedicated 2.4 GHz IoT Wi-Fi network using the mobile app.
  2. Assign a static DHCP lease on your local router.
  3. Add the device in Home Assistant using the native Tinxy Local integration or local MQTT mode. Communication occurs entirely over LAN without routing through external servers.
  4. In your router firewall settings, add a rule to block all WAN egress for the Tinxy switch IP addresses. The switches continue to operate smoothly on the local network. closes O-10

5. Verification & Manual Override Gate

Run the two mandatory failure-mode tests before closing switchboard plates:

  1. Offline local control test (O-10): Unplug the router's WAN / internet cable. Toggle each light and fan from the Home Assistant dashboard. Loads must react with sub-50ms latency.
  2. Server failure manual override test (O-18): Stop the Home Assistant container (docker stop homeassistant). Flip each physical wall switch toggle. Every load must switch on and off instantly without delay or reboot loops. The physical switch must remain a switch regardless of server status.
Pass — Stage 4 Switch Plate Gate

All three switch plates are safely installed, verified with neutral conductors present, operate 100% locally with zero cloud traffic on Espressif ESP8266 hardware, and mechanical wall toggles retain instant manual override even with the server completely halted.
