Stage 1 — Server Setup (SRV-1 / SRV-2)

Bringing up the Radxa Zero 3E as the local headless home automation server. This must be completed first so that Home Assistant is running on the local network to accept Matter and Thread integrations.

Stage 1 Objective

Deploy Debian 13 Minimal (Armbian vendor 6.1 kernel), Docker Engine, and Home Assistant Container on the Radxa Zero 3E. Verify baseline memory footprint (~564 MiB total, ~254 MiB container, < 1 MiB swap) and confirm 100% offline local survivability with the router's WAN unplugged.

1. Image Selection & Download

  • Target board: Radxa Zero 3E (Rockchip RK3566 quad-core Cortex-A55, Gigabit Ethernet — full specs in Server Component Guide).
  • Distribution: Armbian Debian 13 (Trixie) Minimal (CLI), Rockchip vendor 6.1 kernel.
  • Rationale: Idle memory footprint of only ~80–110 MiB, zero desktop/display server overhead, and proven Rockchip vendor 6.1 driver stability for the RK3566 SoC.

Download the image archive from the Armbian Radxa Zero 3 repository (under Minimal / IOT) and decompress the .xz file on your flashing host:

xz -d -k Armbian_*_Radxa-zero3_trixie_vendor_6.1.*_minimal.img.xz

2. Flashing the Micro-SD Card (Linux CLI)

Insert your high-endurance 32 GB micro-SD card (A1/A2 rated) and identify its block device identifier:

lsblk
Target raw disk, not a partition

Always flash to the raw device identifier (e.g. /dev/sdb). Never target an individual partition like /dev/sdb1, which will corrupt partition tables and fail to boot.

Unmount any auto-mounted partitions from the card:

sudo umount /dev/sdb* 2>/dev/null

Write the decompressed image with synchronized hardware flushing:

sudo dd if=Armbian_*_Radxa-zero3_trixie_vendor_6.1.*_minimal.img of=/dev/sdb bs=4M status=progress conv=fsync

Wait until dd exits completely and returns to the shell prompt before disconnecting the card.

3. Network Discovery & First Boot

  1. Insert the flashed micro-SD card into the Radxa Zero 3E card slot on the underside of the PCB.
  2. Connect an Ethernet patch cable from your local network switch/router to the onboard RJ45 Gigabit port.
  3. Connect a clean 5 V / 3 A USB-C power supply to the outer USB-C port marked PWR.
  4. Allow 30–45 seconds for first-boot partition auto-expansion, filesystem generation, and DHCP address acquisition.

Locate the board's IP address by running an ARP/ping sweep across your local subnet:

sudo nmap -sn 192.168.88.0/24

Establish initial SSH connection as root:

ssh root@<RADXA_IP>

Default credentials: password 1234. Follow the on-screen prompt to configure a strong root password and set your shell.

4. User Configuration & Sudo Hardening

Create a dedicated standard user and configure sudo privileges without root dependency:

# Create operator account and add to sudo group
adduser pannet1
usermod -aG sudo pannet1

# Ensure sudo is installed and configure sudoers rule
apt update && apt install -y sudo
echo "pannet1 ALL=(ALL:ALL) ALL" > /etc/sudoers.d/pannet1
chmod 0440 /etc/sudoers.d/pannet1

# Exit root session
exit

5. Base System Update & Docker Engine

Log back into the SBC as the new standard operator user:

ssh pannet1@<RADXA_IP>

Update package repositories and installed packages:

sudo apt update && sudo apt upgrade -y

Install upstream Docker Engine using the official convenience script:

curl -fsSL https://get.docker.com -o get-docker.sh
sudo sh get-docker.sh
sudo usermod -aG docker $USER
sudo usermod -aG dialout $USER
newgrp docker

6. Deploy Home Assistant Container

Create the host directory for persistent Home Assistant configuration and SQLite database storage:

mkdir -p ~/homeassistant/config

Deploy the production container with host networking and privileged hardware access:

docker run -d \
  --name homeassistant \
  --privileged \
  --restart=unless-stopped \
  -e TZ=Asia/Kolkata \
  -v ~/homeassistant/config:/config \
  --network=host \
  ghcr.io/home-assistant/home-assistant:stable
ParameterPurpose in this build
--privilegedGrants the container direct access to host serial devices (GPIO UART /dev/ttyS* and USB) — necessary for the ESP32-H2 Thread radio in Stage 2 (BR-1).
--network=hostRequired for mDNS discovery, SSDP, Matter/Thread device discovery, and zero-NAT latency to local Wi-Fi switchboards.
-e TZ=Asia/KolkataSets container clock to local Indian Standard Time — critical for bedroom time-based rules (BR-01).
-v ~/homeassistant/config:/configBinds persistent configs, database, and automations to host storage for easy off-device backup.
--restart=unless-stoppedEnsures HA restarts automatically on power restore after an outage.

7. Verification & Local-First Pass Gate

Verify container health and resource consumption directly on the host:

# Check container CPU and memory footprint
docker stats homeassistant --no-stream

# Check host physical memory baseline
free -h

Open your browser on the local network and navigate to:

http://<RADXA_IP>:8123
Pass — Stage 1 Server Gate

Home Assistant starts cleanly after a host reboot, is reachable on the local LAN, retains configuration, verified memory baseline sits at ~564 MiB total (~254 MiB container, < 1 MiB swap), and remains fully operational and responsive when the router's WAN / internet cable is unplugged.
