Local Transport

The sensor must be local-first, but the mains actuator should remain a purchased, certified device. Home Assistant on the existing SBC is the local bridge between the custom sensor and a supported Tuya actuator.

Decision

Use ESPHome over the local Wi-Fi network to Home Assistant. Home Assistant runs the presence/light rules and sends local on/off commands through tuya-local to the AZIOT candidate. The fan itself does not need a Tuya profile; only the wall switch and its relay datapoints do. The Tuya cloud may remain enabled for setup, updates, or optional remote access, but the exact revision must prove that basic automation continues when the internet is disconnected for an extended test.

Local-first acceptance test

  1. Pair and configure the Tuya device while internet is available.
  2. Confirm the exact model is listed in tuya-local and exposes the required local on/off relay entities.
  3. Keep the SBC, access point, sensor, and actuator powered; disconnect only the internet/WAN.
  4. Leave it offline overnight or for the longest practical household test. Verify presence, lux-based light automation, fan on/off, light on/off, and manual wall control repeatedly.
  5. Only then conceal the actuator. If local control fails or becomes unreliable, return it and choose another device.
Do not replace Tuya DNS

tuya-local is not a DNS replacement. It connects to the device’s local IP using its local key and datapoints. DNS hijacking can break TLS, pairing, firmware updates, time services, and cloud recovery, while not fixing an actuator whose firmware requires cloud contact. If desired, use a router firewall to block WAN only after commissioning, then test the exact device. The integration documentation warns that some devices stop responding after extended cloud loss.

No useless history

Presence and lux are control inputs, not a data-collection project. Do not build dashboards or retain long-term sensor history. Use transient entity state, short timers, and a small recorder exclusion for sensor entities if desired. Keep only Home Assistant logs needed to diagnose a failed automation.
