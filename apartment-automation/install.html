Install Order

Five stages, in that order. Software and compatibility get proven on the bench before any conductor is disturbed — the sequence itself is the safety mechanism.

The mains boundary

The Aziot plate goes in with a qualified electrician. Everything on this page before Stage 4 is low-voltage and yours. Two checks to hand over: neutral present at the switchboard, and the relay rated for the ceiling fan's starting current, not just its running current.

The five stages

Stage 1 — Bench the sensor

  1. Flash Seeed Studio XIAO nRF52840 with zephyr.uf2 via mass storage drag-and-drop (Sentinel firmware · assembly guide).
  2. Wire radar UART (D6/D7), interrupt (D3), LDO gate (D2), and LiPo cell.
  3. Pair with Home Assistant via native Matter QR-code scan over Thread (walkthrough in the Sentinel video at 3:17).
  4. Run 2-minute auto-threshold routine to map room noise. Verify occupancy and distance entities report immediately (video at 4:49).
  5. Fit into the 3D-printed ball-and-socket enclosure (STLs on GitHub).
Pass

Matter device pairs cleanly over Thread, reports occupancy within ~1 s, auto-threshold calibrated, and battery level monitored.

Stage 2 — Server

  1. Radxa Zero 3E: flash Armbian Debian 13 Minimal, set up user, configure static DHCP lease. Setup procedure.
  2. Time zone Asia/Kolkata — the bedroom rule is time-based and fails silently on a wrong clock.
  3. Deploy Home Assistant Container via Docker with --network=host and --privileged.
  4. Verify memory baseline (~564 MiB total, ~254 MiB container, < 1 MiB swap).
  5. Reboot: HA must return without intervention. Unplug the WAN cable — HA must stay reachable.
  6. Take a backup of ~/homeassistant/config and copy it off the device.
Pass

HA starts after reboot, is reachable on the LAN, retains config, verified memory baseline at ~564 MiB, and works with the WAN unplugged.

Stage 3 — Thread border router

The board is not the border router

Plugging the ESP32-H2 into the Radxa gives you a radio, not a border router. Three things are needed: RCP firmware on the H2, otbr-agent on the Radxa, and a Thread dataset (network key, PAN ID, PSKc) shared to every node.

  1. Flash RCP firmware on the H2. Verify the OS sees the USB device.
  2. Install and start the border-router service on the Radxa. Confirm the Thread network appears and survives a reboot.
  3. Confirm HA can use this Thread network (Settings → Devices → Add → Thread). O-08
  4. Commission a known-good Thread device first — any off-the-shelf sensor. Remove and re-add it. Closes O-07, the single biggest unknown in the build.
  5. Test state reporting with the WAN unplugged.
  6. Leave both services up for 24 h and check load, memory and USB — O-09.
  7. Record firmware versions, service versions, and the dataset location.
Pass

A known-good device commissions, reports state locally, and still does after a host reboot with WAN disconnected.

Stage 4 — Aziot 3+1 switch plates and door sensor

  1. Electrician: confirm neutral at each room's switchboard (Hall, Study, Bathroom). Closes O-11.
  2. Fit one Aziot 3+1 Fan Smart Switch module per switchboard behind the switches; keep physical wall switches connected.
  3. Pair with Wi-Fi / HA via local Tuya integration. Name each channel: Hall Light, Hall Fan, Study Light, Study Fan, Bathroom Light, Bathroom Exhaust Fan.
  4. Toggle each load from HA with the WAN unplugged. State must match physical load. closes O-10
  5. Reboot server, repeat. Confirm wall toggle switches override instantly. closes O-18
  6. Assemble Option 1 DIY Matter-over-Thread door sensor (XIAO ESP32-C6 + MC-38 reed switch + 2,000mAh LiPo), commission into Home Assistant via Matter QR code, mount on bathroom door exterior frame, and verify sub-80ms open/close triggers locally. O-12
  7. Record entity IDs, integration name, firmware versions.
Fail if

The loads only move through a vendor app, or state doesn't update. Resolve local control before any load is switched automatically — never after.

Stage 5 — Commission and mount

  1. Run each room's tests against the approved parameters, one room at a time. HA automations.
  2. Verify manual control works for every load with HA stopped — the wall switch must still be the wall switch. Closes O-18.
  3. Mount the sensors at the surveyed positions. Placement.
  4. Retest false positives against the real ceiling fan and adjacent rooms; tune the distance gates.
  5. Leave the automations disabled until each room's tests pass.

Maintenance routine

TaskHow
OTA a sleepy sensorSet poll_period: 0 → flash → restore. OTA is broken while poll_period > 0.
API disconnectsKeep the poll period under 60 s or the native API times out.
Swap a cellUnplug, replace, confirm battery voltage entity reports. Target swap every 12 months for strategy B.
After a power cutCheck the Thread network reformed and the plate reconnected before relying on automation.
BackupsHA backup to a separate device, monthly. Verify it restores.
